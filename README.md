# 競馬予想AI（前日情報ベース・2モデル構成）

前日までに確定している情報だけを使って予想し、性格の異なる2つのモデルの結果と、
レース単位の自信度を出力します。

## 構成

| モデル | 目的変数 | オッズ | 狙い | 向く券種 |
|---|---|---|---|---|
| **A: 的中率重視** | 3着以内 | **使わない** | 市場と独立した純粋な能力評価 | 複勝・ワイド |
| **B: 期待値重視** | 1着 | **前日オッズを使用** | 市場情報を取り込んだ高精度な勝率推定 → 期待値計算 | 単勝・馬連 |

Aはオッズを見ないので「人気だから上位」という循環が起きず、市場との乖離＝妙味の発見にも使えます。
Bは市場情報を取り込むぶん勝率推定は正確になりますが、そのままだと人気馬をなぞるだけなので、
**推定勝率 × オッズ = 期待値** が1.0を超える馬だけを買う、という使い方をします。

## ディレクトリ

```

src/features.py     特徴量生成（すべて過去情報のみ）

```

### データ取得についての制約

**前日オッズは過去に遡って取得できません。** netkeiba の過去レースページに残っているのは
確定オッズ（発走時点）だけです。検証では確定オッズを前日オッズの代わりに使っています。
確定オッズの方が直前情報を含むぶん情報量が多いので、検証結果は実運用よりやや良く出ます。
馬場状態も同様で、検証では実際の馬場を、運用では前日の予報を使うことになります。
この差は結果を見るときに割り引いてください。

**血統（種牡馬）は取得していません。** 馬ごとに別ページへのアクセスが必要で、
リクエスト数が数倍になるためです。`sire_id` 列があれば自動で血統特徴量が有効になります。

アクセス間隔は1秒に設定しています。netkeiba の利用規約を確認のうえ、個人利用の範囲で使ってください。
公式かつ確実な手段が必要なら JRA-VAN Data Lab（有料）を検討してください。

## バックグラウンドで動かす（GitHub Actions）

Colab はタブを離れると切断されます。放置して収集を終わらせたい場合は GitHub Actions を使います。
実行が GitHub のサーバー側で走るので、スマホの電源を切っていても進みます。

セットアップはノートブックの「スマホを閉じても続くようにする」のセルから行えます
（`scripts/push_to_github.py` がリポジトリを作って一式を置きます）。手動なら、このリポジトリを
そのまま GitHub に push してから:

1. Actions →「データ収集」→ Run workflow
2. Settings → Pages で Source を `main` / `docs` に
3. 収集完了後に「学習と予想の公開」が自動で走り、`https://<ユーザー名>.github.io/<リポジトリ>/` で見られる

| ワークフロー | いつ動くか | 何をするか |
|---|---|---|
| `collect.yml` | 手動 + 6時間ごと | 1回あたり最大5時間ぶん収集して `data/` にコミット。残りは次回に持ち越し |
| `predict.yml` | 収集の完了時 + 毎週金曜 | 学習・8〜9月で検証・`docs/index.html` を更新 |
| `horses.yml` | 手動 + 6時間ごと | 馬の戦績ページから通過順・ペース・上がり3F を補完 |
| `cloudflare.yml` | 学習の完了時（任意） | Cloudflare Pages にデプロイ。private のまま URL で見たい場合に使う |

### private リポジトリで使う

private にすると GitHub Pages は使えません（有料プラン限定）。選択肢は3つ。

1. **収集だけ GitHub、ページ作りは Colab**（いちばん手軽）
   `scripts/colab_publish.py` の `publish_to_drive()` が private リポジトリから**データだけ**を取得し、
   **ノートブックが持つ最新のコード**で学習して Google Drive に `予想.html` を置きます。
   リポジトリ側のコードが古くても、ノートブックを差し替えれば最新の処理で動きます。
2. **Cloudflare Pages**（URL が欲しい場合）
   `cloudflare.yml` にシークレットを3つ登録すれば、private のまま自動デプロイされます。無料。
3. **公開用の別リポジトリを作る**
   データは private のまま、`docs/index.html` だけを公開用リポジトリに push して Pages を使う。

なお private リポジトリの Actions 無料枠は月2,000分です。収集は約180分なので収まります。

収集は開催日単位でチェックポイントを取ります。ジョブが時間切れになっても、その日を最後まで
回れていなければ未完了のままにするので、取りこぼしも二重取得も起きません。

## 必要なデータ

1行 = 1レース1頭。過去3〜5年分（3万行以上）が最低ライン、10年分あると安定します。

**必須列**

```
race_id, date, horse_id, venue, surface(芝/ダ), distance, turn(右/左),
class_level(1〜6の数値), horse_no, frame_no, age, sex, weight_carried,
jockey_id, trainer_id, sire_id, going_forecast, odds_prev_win, finish_pos
```

スクレイパーはこれに加えて `corner_pos`（通過順）、`prize`（賞金）、`last3f`（上がり3F）、
全券種の払戻を取得します。通過順からは脚質、賞金からは実績が特徴量として作られます。

**あると精度が上がる列**

```
odds_prev_place_low   前日複勝オッズ下限
training_time_last    最終追い切りタイム
last3f                上がり3F（過去走の特徴量として自動利用）
payout_win/payout_place  バックテストの回収率計算に必要
```

データ取得は JRA-VAN Data Lab（有料・公式）か netkeiba のスクレイピングが一般的です。
スクレイピングする場合は各サイトの利用規約とアクセス間隔に注意してください。

## 使い方

```python
import pandas as pd
from src.predict import KeibaPredictor, format_report

history = pd.read_csv("history.csv")   # 過去の全レース結果
entries = pd.read_csv("tomorrow.csv")  # 明日の出走表（finish_pos なし、前日オッズあり）

p = KeibaPredictor().train(history)
pred = p.predict_day(history, entries)          # ← history と結合して特徴量を作るので両方渡す
reports = p.build_report(pred, min_grade="A", top_n=5)
print(format_report(reports))
```

`min_grade="A"` で自信度A級以上のレースだけに絞り込みます。`top_n` で点数を制限。

## 自信度の仕組み

レースごとに次の4つを合成してスコア化します。

1. **突出度** — 本命馬の確率そのもの
2. **差** — 1位と2位の確率差（2強なら低い）
3. **混戦度** — 正規化エントロピー（横並びなら読めない）
4. **一致度** — AとBの本命が一致するか（市場と独自評価の合致）

スコアはそのままでは意味がないので、バックテストの実測的中率でキャリブレートして
S/A/B/C に落とします。合成データでの検証例：

```
grade  レース数  A複勝的中率  B単勝的中率
S        153     77.8%      49.7%
A        229     67.7%      45.4%
B        381     62.2%      39.4%
C        763     49.0%      26.7%
```

C級を捨ててS/A級だけ買う、という運用が想定用途です。

## データリーク対策

競馬予想モデルで最も多い失敗が、当日情報の混入です。`src/schema.py` の `LEAK_COLS` に
**馬体重・確定オッズ・確定人気・上がり3F・通過順・実馬場状態**を列挙し、
特徴量選択時に機械的に排除しています。列を追加するときは必ずこのリストを更新してください。

集計特徴量（馬の勝率、騎手の成績など）も `cumsum - 自分自身` 方式で
「そのレースより前のデータのみ」から計算しています。ランダム交差検証は使わず、
ウォークフォワード（過去で学習→未来で検証→窓をずらす）のみで評価します。

## スマホで見る

`build_site.py` が学習から予想ページの書き出しまでを一気に実行します。

```bash
python build_site.py --demo                                  # サンプルで動作確認
python build_site.py --history history.csv --entries tomorrow.csv
```

`予想.html` が1ファイルで完結する形（データ埋め込み済み・通信不要）で出力されます。
スマホで見る方法は3つ。

1. **ファイルを転送する** — AirDrop / LINE / Google Drive などで `予想.html` をスマホに送り、ブラウザで開く。オフラインで動きます。
2. **同じWi-Fiで見る** — PC で `python serve.py` を実行し、表示された `http://192.168.x.x:8000/予想.html` をスマホで開く。ホーム画面に追加すればアプリのように起動できます。
3. **常時アクセスしたい場合** — 出力した HTML を GitHub Pages / Netlify / Cloudflare Pages に置く。静的ファイル1枚なので無料枠で足ります。前日夜に `build_site.py` を cron で回して自動更新するのが実用的です。

**Google Drive アプリのプレビューは JavaScript を実行しない**ため、対話式ビューアでは
中身が表示されない。同時に出力される `予想_静的.html`（`src/static_report.py`）は
全レース・全買い目を最初から HTML に書き出すので、どの環境でも読める。
絞り込みや券種の切り替えはできないかわりに、確実に表示される。

ページの操作:

- 上部の「格付け」で S / A以上 / B以上 に絞り込み
- 「当てにいく」＝モデルA（オッズ非考慮・的中率重視）、「妙味を狙う」＝モデルB（期待値重視）
- レースをタップで出馬表と買い目を展開、券種タブで馬連 / 馬単 / 3連複 / 3連単 を切り替え

## 連勝式の確率計算

単勝の勝率から2着・3着の確率を出すのに、Lo & Bacon-Shone の指数割引モデルを使っています。

```
P(1着a)     = s_a / Σs
P(2着b|a)   = s_b^λ2 / Σ_{j≠a} s_j^λ2      λ2 ≈ 0.81
P(3着c|a,b) = s_c^λ3 / Σ_{j≠a,b} s_j^λ3    λ3 ≈ 0.65
```

素朴な Harville モデル（λ=1、2着以降も同じ強さ比で配分）は人気馬の連対率を
過大評価することが知られています。λ<1 は「2着・3着争いは1着争いより混戦になる」
という実際の傾向を表します。λ は `fit_lambdas()` で自分のデータから推定し直せます。

連勝式のオッズが手元にない場合は、前日単勝オッズから市場の勝率を復元し、
同じモデルで推定配当を計算しています。実オッズがあれば `build_bets(actual_odds=...)`
に渡してください。そちらの方が当然正確です。

## これから走るレースを予想する

過去結果とは別に、出馬表を取得する必要があります（`src/netkeiba_live.py`）。

```bash
python scripts/predict_day.py --date 2026-09-20
python scripts/predict_day.py --date 2026-09-20 --seed-race-id 202609040811
```

`docs/next.html` が出力されます。Colab から使う場合はノートブックの9章を実行してください。

**タイミング** — 出馬表は木曜に確定、前日オッズは前日の夜に出そろいます。
モデルAはオッズを使わないので木曜から動かせます。

**オッズ** — 出馬表ページのオッズ欄は JavaScript で後から埋まるため HTML には載っていませんが、
netkeiba が内部で使っている JSON API から取得できます。

```
https://race.netkeiba.com/api/api_get_jra_odds.html?race_id=<12桁>&type=<1-8>
```

`src/netkeiba_live.py` の `fetch_all_odds()` がこれを叩き、**単勝・複勝・馬連・馬単・
ワイド・3連複・3連単**を取ります。式別の番号割り当ては変わりうるので、番号を決め打ちせず
「キーの形（2桁=単勝、4桁=2頭、6桁=3頭）」と「逆順の組み合わせが存在するか（馬連か馬単か）」
「値が範囲か（馬連かワイドか）」から中身を判定しています。

連勝式の実オッズが取れると、期待値を推定配当ではなく**実配当**で計算できます。
取れなかった券種は単勝オッズからの推定にフォールバックし、画面に「配当は推定」と表示されます。

万一すべて取れなくても、**モデルA（的中率重視）はオッズを一切使わないのでそのまま動きます**。
`apply_manual_odds()` による手入力も残してあります。

**レース一覧が取れない場合** — netkeiba でその日のレースを1つ開き、URL の `race_id` を
`--seed-race-id` に渡してください。出馬表ページには同じ日の他レースへのリンクが載っているので、
そこから全レースを辿ります。

## 走破タイムを使った独自の特徴量

netkeiba が通過順と上がり3F を有料化したため本来のペース（前半3F の速さ）は
計算できないが、走破タイムは取得できる。そこから3つの特徴量群を作っている
（`src/timeform.py`）。

### 1. 基準タイム

コース・距離・馬場種別ごとの勝ちタイムの平均。過去のレースだけから作る。

### 0. 馬の戦績ページによる補完

レース結果ページ（`db.netkeiba.com/race/...`）からは通過順と上がり3F が
取得できなくなったが、**馬の戦績ページ（`db.netkeiba.com/horse/result/{id}/`）には
残っている**。しかも「ペース」列で前半3F と後半3F が取れる。

```
通過   4-4-3-3      各コーナーの位置取り
ペース 34.9-35.1    前半3F - 後半3F
上り   34.1         上がり3F
```

プレミアム限定なのはタイム指数・馬場指数・スタート指数・厩舎コメントなどで、
これらは値が `**` になっている。上の3つにはその印が無い。

馬1頭につき1リクエストで全出走歴ぶんが手に入るため、レースを個別に回すより
はるかに効率がよい。`scripts/scrape_horses.py` と `horses.yml` で収集する。

前半3F と後半3F の差（`pace_balance`）が負なら前傾ラップ（前半が速い＝先行に厳しい）、
正なら後傾ラップ。これで本来の意味でのペース適性（`pace_apt_front` / `pace_apt_back`）
が作れる。

### 2. 馬場差（当日補正）

**同じ日・同じ場・同じ馬場種別で、それより前に行われたレース**の勝ちタイムが
基準よりどれだけ速いかの平均。1〜6R の結果から 7〜12R の馬場状態を推し量る。
前例が無い場合（1R など）は、その場の直近開催日の馬場差で代用する。

芝とダートは別々に集計する（馬場差は別物のため）。合成データでの検証結果:

| レース番号 | 当日データ使用率 | 真の馬場差との相関 |
|---|---|---|
| 1R | 0% | 0.05 |
| 4R | 85% | 0.78 |
| 7R | 98% | 0.88 |
| 12R | 99% | 0.93 |

7〜12R では相関0.91、推定誤差0.17秒（真のばらつき0.56秒）。
当日のレースしか使わないので、予想時点で必ず手に入る情報になる。

### 3. タイム指数とペース適性

`基準タイム − 走破タイム − 馬場差` を秒で表したもの。着順は相手次第で変わるが、
タイム指数は相手に依らない物差しになる。ここから

- `speed_avg` / `speed_best3` / `speed_trend` — 馬の絶対能力
- `apt_fast` / `apt_slow` / `apt_gap` — 速い決着と遅い決着のどちらに強いか
- `pace_expect` — 出走馬の指数から見積もる、そのレースの想定決着水準
- `pace_fit` — 適性 × 想定ペース。噛み合わせの良さ
- `variant_fit` — 適性 × 当日の馬場差

を作る。`apt_*` が本来のペース適性の代わりになる。

### リーク防止

タイム指数は当該レースの走破タイムから作られるため、そのまま特徴量に入れると
完全なリークになる。`finish_time` `time_sec` `speed_fig` `race_dev` `race_dev_adj`
`day_dev` を `LEAK_COLS` に登録し、機械的に排除している。
馬ごとの集計は前走以前のみ、馬場差は同日でも自分より前のレースのみ。

## 精度を上げるための次の一手

- **ペース・脚質**：過去走の通過順から逃げ/先行/差し/追込を分類し、レースの想定ペースと組み合わせる
- **タイム指数**：走破タイムを馬場差・距離・クラスで補正した独自指数（スピード指数系）
- **枠順×コース**：コース別の枠順有利不利は距離ごとに大きく異なるので交互作用を明示的に入れる
- **ラベルの工夫**：着順そのものより着差ベースの連続値で学習した方が情報量が多い
- **LambdaRank**：レース内の順位付けに特化した学習目的に切り替える
- **連勝式オッズの取り込み**：馬連・3連複の実オッズを前日に取得できれば、推定配当ではなく実配当で期待値を計算できる。妙味の判定精度が大きく変わる

## 現実的な注意

- JRAの控除率は単勝約20%、馬連約22.5%、3連単約27.5%です。何もしなければ回収率は
  その分だけマイナスから始まります。合成データでも期待値フィルタ後の単勝回収率は
  90%前後にとどまり、控除率の壁を越えるのは容易ではないことが確認できます。
- 「的中率が高い」ことと「儲かる」ことは別です。本命を買えば的中率は上がりますが
  回収率は上がりません。モデルAは的中率、モデルBは回収率、と役割を分けているのはそのためです。
- バックテストの成績は、パラメータをいじるほど楽観的になります（過学習）。
  検証期間の最後の1年は一度も触らずに取っておき、最終確認だけに使ってください。
- 3連単は控除率27.5%と最も不利な券種です。当たれば大きいぶん、長期的な期待値は最も削られます。回収率を重視するなら馬連・ワイドの方が土俵として有利です。
- 合成データのデモで一部の回収率が100%を超えていますが、これはダミーの市場オッズが甘いだけで、実データでこの数字は出ません。必ず自分のデータでバックテストしてください。
